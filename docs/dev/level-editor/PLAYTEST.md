# Play-test loop (M3)

Play starts a fresh run; Resume continues its timer and trail. Returning to Edit freezes both. Show trail displays the last 60 seconds, sampled at 60 simulation frames per second: green on ground, blue in air, orange diving and purple bouncing off Cappy. Gold diamonds mark the change from rising to falling along Mario's local gravity. Teleports and time spent in Edit break the line. The timer keeps counting after the trail's sixty-second buffer wraps.

After a play-test, select a moved object and press K, or choose Keep played transform in the Inspector. Keep copies its current position, rotation and scale into the layout in the object's zone coordinates. This is one undo step for the whole selection. It requires a catalog-verified keepable class and a live actor; path riders, child objects and collected or defeated actors have an explanation instead. A mixed selection containing an ineligible object is rejected in full. Play-test movement never writes layout changes automatically.

Collecting a Power Star in a play-test releases Mario's binding, retires the star and returns to Edit with a `Cleared in m:ss` toast. The hook runs before star progress, the get cutscene and the stage-result sequence. Ordinary play retains the original star behavior. Runtime owns the edit session's scratch save and progress snapshot; the Trail and star adapter subscribe to its Begin, Resume, ToEdit and End events.

`native_editor_playtest` tests retention, pause/resume/reset, gravity-relative peaks, discontinuities, zone transforms and atomic Keep/undo. `native/tools/editor_playtest_smoke.py` runs an isolated Good Egg session: a real Mario jump, a naturally moved keepable actor, Keep/undo, Resume, and a Power Star placed within Mario’s reach for collection. It captures `playtest-trail` and `playtest-cleared`. Save-isolation tests belong to Runtime's lifecycle suite.
